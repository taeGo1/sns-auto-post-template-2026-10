# ハルシネーション検証ミッション

sns-posts.json の各投稿が、事実と矛盾していないかチェック。
問題があれば**最小限の修正**を加えて上書き保存する。

# ⚠️ 過剰修正の絶対禁止（最重要）

書き手の個性・口調・リズム・改行・記号は**絶対に壊さない**。
判断に迷ったら **必ず「修正しない」を選ぶ**。
ハルシネーションチェックは**明らかに事実と異なる**箇所に限定する。

### 修正対象外（絶対に触らない）

- 書き手の**感想・気づき・心境**（「気がする」「印象として」「思った」「驚いた」など事実主張でない表現）
- **比喩・例え話**（「料理に例えると」など）
- **個性的な口調・リズム・改行・記号**（「、、、、」「←」「【ガチ】」「【保存版】」「、、、」など）
- **一般的な事実**（プロフィール記載が無くても、世間で広く知られている事実）
- **曖昧な感想表現**（「結構」「かなり」「めちゃくちゃ」「ほんと」など）
- **テーマ上の選数**（「8選」「20パターン」「30種」など投稿の構成数字）

# 入力ファイル

- `hallucination_rules.md` ：検証ルール定義（enabled: true のものだけ適用）
- `${{ runner.temp }}/sns-posts.json` ：検証対象（投稿2件。空の配列なら何もしない）
- `${{ runner.temp }}/sns-context.json` ：事実根拠（公式サイトテキスト・プロフィール）

# 作業手順

**Step 1**：Read tool で `hallucination_rules.md` を読む（enabled: true のルールのみ適用）

**Step 2**：Read tool で `${{ runner.temp }}/sns-posts.json` を読む

**Step 3**：Read tool で `${{ runner.temp }}/sns-context.json` を読む

**Step 4**：各投稿の post_text に対して、enabled: true のルールを適用
（「架空の話・作り話」は厳禁。作者の体験・使用感・聞いた話・架空の事例が書かれていたら `tonmana.md` を Read して確かめ、無い話は**その文を削除**する。ここは「迷ったら直さない」の例外で、迷ったら削除する。削除して文字数が下限を割っても、削除を優先する）

### 機械の照合の結果を使う（人に確認を回さない）
- 指示で渡された `evidence-check.json`（機械の照合の結果）を Read する。**根拠の無い行は、プログラムがすでに投稿から削除してある**（`removed_lines`）。削除された行を**戻さない・言い換えて書き直さない**
- 残っている各投稿の `evidence` の `sentence` と `quote` を見比べ、**意味が同じか・言いすぎていないか**を確かめる。英語の原文と日本語の文の意味がずれている、原文に無いこと（「誰でも簡単に」「大幅に」「〜限定」の取り違えなど）を足している → **その文を削除**する
- `official_evidence` の話題で、見出し（ポータル記事など）にしか無い内容が残っていたら削除する
- 迷ったら削除する。人に確認を回さない。新しい事実・新しい文は足さない
- 削除で話がつながらなくなったら、前後の「つなぎ」の言葉だけ最小限に直す（「つまり、」を外す・👇を動かす など）
- 削除した文は `sns-validation.json` の `modifications` に「削除：〇〇（理由）」として残す。削除した文に対応する `evidence` の項目も消す

### 各ルールの判定原則
- **明確な違反**のみ修正対象
- 曖昧・判断つかない場合は **そのまま残す**（過剰修正防止）
- 修正は**最小限**。元の文章のリズム・口調・改行・記号は全部維持
- 修正後も文字数は context.post_length_min 〜 post_length_max を維持
- sources（参照元URL）が空でも修正対象としない（任意フィールド）

**Step 5**：問題があった投稿のみ post_text を最小限修正、Write tool で `${{ runner.temp }}/sns-posts.json` を上書き
（問題がなければ上書き不要・触らない）

**Step 6**：Write tool で `${{ runner.temp }}/sns-validation.json` に検証結果を保存：

```json
{
  "post_1": {
    "status": "pass" または "modified",
    "issues_found": ["違反内容①", "②"],
    "modifications": ["修正前の該当箇所 → 修正後の該当箇所"]
  },
  "post_2": { ... },
  "summary": {
    "total_issues": N,
    "modified_posts": M,
    "rules_applied": ["rule1", "rule2", ...]
  }
}
```

問題がなければ status: "pass"、issues_found: []、modifications: [] のまま記録。

完了したら、修正件数を1行で報告してください（例：「2件チェック・修正0件」）。
