# 話題を集める先を決める（毎回・最初の段）

このリポジトリの持ち主の「読む人」に合わせて、今日の話題を集める先（ニュースの検索語・公式ブログやメディアの RSS）を決めます。
ここは仕組みの一部なので、受講生は書き換えなくて大丈夫です（集める先を自分で決めたいときは `settings.yml` に書きます）。

## 読むファイル
1. `prompts/reader.md`（読む人・強い話題）
2. `tonmana.md` と `examples/` の投稿（どんな分野の発信か）
3. `settings.yml` の `collect`（持ち主が自分で書いた集める先。書いてあれば必ず入れる）

## 決め方
- 読む人が「え、なにそれ見たい」と思う話題が出てくる場所を選ぶ
  - その分野で読む人が使っている**道具・サービスの公式のお知らせ**（公式ブログ・ニュースルーム・リリースノートの RSS）
  - その分野の**信頼できるメディア**の RSS
  - **ニュースの検索語**（日本語・英語。道具やサービスの名前＋「新機能」「アップデート」など）
- RSS の URL は、WebSearch と WebFetch で**実際に読めることを確かめたものだけ**入れる（推測で URL を作らない）
- 読む人がまだ空のときは、`examples/` と `tonmana.md` から分野を読み取る。どれも空なら、幅広い人が使うアプリ・サービスの新機能が見つかる検索語にする
- 個人ブログ・まとめサイト・転載サイトは入れない

## 出力（`sources.json` に Write する。JSON だけ）
```json
{
  "field": "どんな分野の発信か（1行）",
  "news_keywords_ja": ["検索語（3〜8個）"],
  "news_keywords_en": ["英語の検索語（0〜5個）"],
  "rss": [
    {"name": "表示名", "url": "読めることを確かめた RSS の URL", "official": true}
  ],
  "evidence_domains": ["本文を根拠に使ってよいサイトのドメイン（公式・信頼できるメディア。例：example.com）"]
}
```
- `official` は、道具・サービスの公式のお知らせなら true、メディアなら false
- 報告は1行：「集める先：検索語 〇個・RSS 〇個」
