## ここは変えない（事実を守る仕組みが動くために必要）

### 話題
- 投稿1の話題は `context.work_record.topic` → 無ければ `context.chosen_topic.topic`。ここで選び直さない（同じ話題で動画も作られる）
- 投稿2は、`hot_topics`・`official_recent` の中から、根拠（要約・本文）がある別の話題を1つ。`past_posts`（投稿済み）と同じ話題は選ばない。材料が足りなければ短くてよい
- `chosen_topic.angle` が `how_to` の日は、数日前の発表の「使い方・受け取り方の案内」として書く（「今日発表」と書かない）

### 根拠の付け方（機械が照合する）
- 投稿のすべての行は、次のどれかにする。どれにも当たらない行は、プログラムが**自動で削除**する
  1. **事実の行**：`evidence` に、1文ごとに根拠を付ける（`sentence`＝投稿の文をそのまま／`quote`＝根拠の原文を材料から一字一句そのまま・20〜200字／`source`＝出どころ）
  2. **一言の行**（感想・問いかけ・お願い）：`voice_lines` にそのまま入れる。体験の形（「使ってみたら」）・名前・数字は入れない
  3. **解釈の行**（それで何が起きるか・使い方）：`insight_lines` にそのまま入れる。新しい名前・数字は足さない
  4. **言い換えの行**（用語をかみ砕いた行）：`plain_lines` にそのまま入れる。5行まで
  5. つなぎ（「つまり、」「👇」だけの行）
- 根拠は材料の中だけ：`primary_evidence` の `text`（公式・信頼できる媒体の本文）・`hot_topics` と `media_articles` の要約・`work_record`（試した記録）
- **根拠を付けられない事実は書かない**。コマンド名・機能名は原文の表記のまま
- 「だけ」「のみ」「すべて」「初めて」などの言い切りは、原文に同じ言葉があるときだけ

### 作り話の禁止
- 使ったことの無いものを使ったことにしない。聞いた話・体験談を作らない
- 試した記録の数字は記録どおり。架空のサンプルデータなら、そのことを書く

### 長さ
- `context.post_length_max` 字を超えない。`post_length_min` 字は目安（中身が足りないときに一般論で埋めない）

### 出力（`sns-posts.json` に Write する。JSON だけ・1回で書く。直すときは Edit）
```json
[
  {
    "theme": "投稿1のテーマ（10文字以内）",
    "post_text": "投稿文。1〜2文ごとに改行。Markdown の記号・ハッシュタグは使わない",
    "voice_lines": ["一言の行を post_text からそのまま"],
    "insight_lines": ["解釈の行を post_text からそのまま"],
    "plain_lines": ["言い換えの行を post_text からそのまま"],
    "evidence": [{"sentence": "投稿の事実の文（そのまま）", "quote": "根拠の原文（材料から一字一句そのまま）", "source": "出どころ"}],
    "sources": ["根拠にしたページの URL"]
  },
  { "theme": "投稿2のテーマ", "…": "同じ形" }
]
```
- 分析や下書きを書き出さない。報告は1行：「投稿1：〇〇（〇字）・投稿2：〇〇（〇字）」
