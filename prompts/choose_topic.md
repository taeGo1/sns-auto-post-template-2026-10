## ここは変えない（仕組みが動くために必要）

### 選ぶときの約束
- 上の質問に、いちばん「はい」と言えるものを1つ選ぶ。点数（score）は参考
- **`past_7days`（投稿済み）と同じ主役（同じ機能・同じ発表）は選ばない**。`posted_recently` がある候補も選ばない
- 静かな日の決まりが空なら：今日・昨日の候補から、いちばん読む人に近いものを選ぶ

### 候補の種類（`kind`）
- `new`：今日・昨日の話題で、本文か要約（`summary`）がある
- `headline`：今日・昨日の話題だが、見出ししか取れていない。見出しが強ければ選んでよい。選んだら、WebSearch と WebFetch で、その話の**公式のページ**か**信頼できる媒体の記事**（`evidence_domains` のサイトか大手の報道機関）を探し、見出しの中身が本当に書かれていることを確かめて `evidence_url` に入れる。個人ブログ・まとめ・転載サイトは使わない。**見つからなければ選ばず、次の候補へ**
- `recent_official`：直近の公式の発表（`days_ago` が 0〜1 の今日・昨日の発表もある。本文は選ばれたあとで読む）

### 出力（`topic-choice.json` に Write する。JSON だけ・1回で書く）
```json
{
  "topic": "選んだ候補の title をそのまま（言い換えない・訳さない。title の中の \" は \\\" と書く）",
  "angle": "new（今日・昨日の発表）か how_to（数日前の発表の使い方・受け取り方の案内）",
  "evidence_url": "kind が headline のときだけ：本文を確かめたページの URL（それ以外は空）",
  "why": "なぜ読む人が「え？」と思うか（1〜2行）",
  "reader_use": "読む人がどう使えるか・何が楽になるか（1行・現実味のあることだけ）",
  "backups": [
    {"topic": "2番目に良い候補の title", "angle": "new か how_to", "evidence_url": "headline のときだけ"}
  ],
  "others": [
    {"title": "選ばなかった上位の候補（5つまで）", "why_not": "選ばなかった理由（1行）"}
  ]
}
```
- `backups` は、選んだ話題の本文が読めなかったときの控え（2つまで・良い順）
- 分析や経過は書き出さない。報告は1行：「話題：〇〇」
