# 作業動画のキャプション（クラウド・作業動画の日だけ）— 2026-10-05 作り直し

クラウドで Claude Code に**その日の話題の機能を本当に使わせ**、その記録を動画にしました。
この**実際の作業記録**をもとに、X・Threads・Instagram リール・TikTok の投稿文を書きます。
どう使ったらよいか・どんな使い方があるのかを本当に試し、その動きを見せる。読む人は `prompts/reader.md`。

## 読むファイル
1. 作業記録 `replay.json`（場所は起動時の指示）… `prompt`（頼んだ言葉）・`blocks`（やったこと）・`lanes`（担当ごとの動き。あれば）・`compare`（2通り比べた2回目。あれば）・`feature`（使った機能）・`notes`（動画の説明文字）・`realSeconds`・`resultFile`・`resultPreview`
2. 計画 `work-plan.json`（あれば）または下書き `sns-draft.json` の `demo` … `can_do`（この機能で読む人ができること）・`ideas`（使い方の候補）・`scene`（場面）・`watch`（見えるはずの動き）
4. `sns-studio/rules/SNSの型.md` の「4. 文章」と `tonmana.md`（口調）
5. `tonmana.md`・`hallucination_rules.md`（特にルール9：作り話の体験を書かない）
6. `prompts/reader.md`（読む人）

## 文章の形（4つ・この順）
1. **どう頼んだか**：記録の `prompt` をそのまま（普通の言葉になっている）。1〜2行目は「何ができたか」から（「テストまで書く」ではなく「3人の担当が同時に動いて、一覧が1つにまとまった👇」）
2. **何が起きたか（動き）**：記録どおりに3〜5手順。担当（lanes）があれば「〇〇担当・△△担当・□□担当が同時に動いて」。直し（Edit）があれば「どこを直したか」。比べた（compare）なら「A は〇秒・B は△秒」と記録の数字で、違いを1行（compare.verdict があればそれ）
3. **結果**：できたもの（resultFile・resultPreview の中身）と秒数。数字は成果の数（本数・件数・秒）。**行数・テストの件数・CSV・unittest・python3 は書かない**
4. **こう使える**（「たとえば、こんな使い方ができます」の形。書き手が使っていない道具を「私なら」と書かない。試した記録があるときは「頼んでみると、〇〇でした」と記録どおりに）：`can_do`・`ideas`・`scene` から、読む人（`prompts/reader.md`）が自分の仕事の仕組みに置き換えられる使い方を1つ（単発の作業で終わらせない）。公式の範囲で。数字は作業記録にあるときだけ

- **使った機能の名前は `feature` のとおりに正直に**（例「サブエージェント（担当分け）で試しました」）。使っていない機能（例：Agent teams）を使ったことにしない。話題の機能が「実験的・既定で無効」で代わりの機能を使ったなら、そう書く
- 感想は**素の一言だけ**（「地味に便利」「ここまでやるのか」など）。「断言します」の決め台詞は使わない。**「——」（長いダッシュ）は使わない**（10/5 Threads に出た）
- 「つまり、」で流れを ↓ でまとめ直してよい

## 絶対に守ること
- **記録にないことは書かない。** 作業時間・件数・ファイル名・担当名・エラーは記録どおり
- 作業したのは「Claude Code」。書き手が自分の手で試した体験として書かない（「試したら」ではなく「頼むと」「頼んでみると」）
- データは架空のサンプル。本物の顧客の話として書かない。**結果の数字を書くときは、すぐそばに「（架空のサンプルデータ）」と書く**。「〇%削減」のような効果の数字は見出しや1行目には使わない
- 実績・経歴は入れない
